The problem

A small tank that overflows in every storm,
and a big one with room to spare

  • Manual pumping means watching the weather and remembering to switch it off.
  • Forget for 10 minutes and the pump runs dry: seals gone.
  • Forget in a storm and Tank A spills water you wanted.
  • Goal: unattended, and boringly safe.
The system

One writer, many readers

Hardware

Off-the-shelf parts, plus a pump

Sensor nodes ×2

ESP32-S3 on a screw-terminal base, JSN-SR04T waterproof ultrasonic probe. Median of 5 echoes every 30 s.

Raspberry Pi 3

Broker, controller, dashboard. Lives in a weatherproof box next to Tank A, with the node on a 10 cm USB lead.

Tapo P110M plug

Local API via the tapo library, plus power metering, which doubles as a dry-run detector.

600 W transfer pump

Rated 3,600 L/h at zero head; measured 1,540 L/h up 16 m.

Float switch

Wired in series with the pump. The one safety layer that needs no software.

Extras

7.3" 6-colour e-ink frame, the house's solar inverter, a USB webcam so the agent can see the LEDs.

Safety first

Layers, because every layer fails eventually

  • 1Never pump if Tank A < 20%
  • 2Never pump if Tank B > 95%
  • 3Runtime cap 90 min → OFF + alert
  • 4Sensor silent 120 s → FAULT
  • 5Plug unreachable → OFF
  • 6Hysteresis: start 94%, stop 60%
  • 7Every threshold in config.yaml
  • 8A start needs 3 agreeing readings

Sizing the runtime cap

90 min × 1,540 L/h ≈ 2,300 L. From a 94% start, Tank A can't go below ~46%, even with a frozen sensor. The cap is a calculation, not a guess.

The first estimate was 5× wrong

Two noisy mid-transfer readings said 135 L/min. Settled before/after medians said 25.7. Only measure a still surface.

What went wrong

Five incidents, five rules

A test moved 164 L

A synthetic "95%" on the live broker started the real pump.

→ test data is a command

One echo, 26 minutes

A dead-zone echo read as "100%" and started the pump on a 68% tank.

→ validate against physics; 3 readings

"It's the router"

It wasn't: modem sleep, dirty reconnects, and TX power the board couldn't drive.

→ the node moved to USB

Blind below 66%

The beam found the tank wall; the 60% stop never fired.

→ the runtime cap saved it

The storm went silent

Water rose above the overflow, past the "impossible" limit. Every reading was rejected, so the pump stopped when it mattered most.

→ physics needs a margin for weather

Every one of these is written up in docs/08, with the change it caused.

# 2430 µs ÷ 58 ≈ 42 cm  < 45 cm floor
  • The agent read the journals, saw the level still rising while pumping, and paused the bridge to read raw serial.
  • The echoes were real: water ~8 cm above the overflow.
  • Floor 45 → 30 cm, plus an "overfull" flag; flashed over the Pi's USB.
  • Fault cleared, pump restarted, level fell ~1 cm/min, which matches the measured flow.

The fun bits

Dashboard, e-ink, weather, solar

Mobile dashboard

Tank gauges with threshold markers, pump runtime against the cap, history, Pi health, live-editable config, Force OFF. Static HTML polling a Flask API.

E-ink wall frame

The Pi renders a 6-colour frame; the device wakes every 2 h, downloads 192 KB, refreshes, and sleeps. Runs on a battery; layout changes need no reflash.

Rain forecast

Open-Meteo, cached, informational only. A weather outage can't touch pumping.

Solar

Huawei inverter over Modbus TCP via its dongle, which allows one client, so one persistent connection. Next idea: prefer pumping while exporting.

What's next

Making it boringly safe, for real

1Float switch

A pump-down float in series with the pump supply. Cuts the motor when Tank A is low, even if the sensor, the Pi and the network all fail together.

2Shelly Pro 1PM

Replaces the smart plug: DIN-rail, Ethernet, local API with no cloud, driving a contactor. Its own auto-off timer caps a run even if the Pi dies.

3Isolated network

An IoT VLAN with firewall rules, or the Pi hosting its own WLAN for the nodes. Today anyone on the LAN could publish "Tank A 95%" and start the pump.

4Hydrostatic sensor

A submersible 4–20 mA pressure sensor on the tank floor: no dead zone, no echoes, reads to the bottom, and a broken wire is detectable.

Three of the five incidents were the sensor

Ultrasonic vs hydrostatic

  • ✗ Dead-zone echo started the pump → no dead zone
  • ✗ Blind below 66% → reads to the floor
  • ✗ Storm overfill silenced it → no top limit
  • ✗ Condensation, foam → not affected
  • Costs: a vented cable, a 12–24 V loop supply, an external ADC (ADS1115), and surge protection. Under 3.6 mA = fault, so a broken wire fails safe.
